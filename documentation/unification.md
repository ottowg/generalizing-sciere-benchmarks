# Unification Pipeline

The unification pipeline standardises entity and relation annotations across
GSAP, SciER, and SciNLP so they can be compared on a common label set. It is
controlled via `configs/unification_config.yaml` and applied per-origin (see
below).

## Per-Origin Application

Unification depends on **where the labels come from**, not what data is being
evaluated on:

- **Gold data** → unify with the dataset's own scheme
- **Predictions** → unify with the `trained_on` model's scheme

```python
from unifiedsciere.unification.pipeline import apply_unification_pipeline

# GSAP model predictions: unify with gsap mappings
pred, stats = apply_unification_pipeline(pred, "gsap", apply_to_gold=False, apply_to_predicted=True)

# SciER gold annotations: unify with scier mappings
gold, stats = apply_unification_pipeline(gold, "scier", apply_to_gold=True, apply_to_predicted=False)
```

## Pipeline Steps

```
Load Corpus
  → 1. Merge Stacked (overlapping mentions)
  → 2. Drop Unmapped Labels
  → 3. Map Labels to Unified Schema
  → 4. Dataset-Specific Corrections
  → 5. Normalize Spans
  → Unified Corpus
```

### 1. Merge Stacked Mentions

**Module:** `src/unifiedsciere/unification/merge_stacked.py`

When multiple entity mentions overlap on the same tokens, keep one:

- `prefer_larger: true` → keep the longer span
- `prefer_larger: false` → keep the shorter span

Relations are updated to reference the surviving mention. Self-loops and
duplicates created by merging are removed.

### 2. Drop Unmapped Labels

**Module:** `src/unifiedsciere/unification/label_mapper.py`

Remove mentions whose labels map to `null` in the label mappings. Relations
referencing dropped mentions are also removed.

Dropped labels per dataset:

| GSAP | SciER | SciNLP |
|------|-------|--------|
| URL, ReferenceLink, DatasetGeneric | — | metric |

For relations: see `relation_mappings.yaml` for which relation types map to
`null` and are dropped.

### 3. Map Labels to Unified Schema

**Module:** `src/unifiedsciere/unification/label_mapper.py`

Transform dataset-specific labels to the unified set. The original label is
preserved in `mention.label_original`.

Entity mappings: `src/unifiedsciere/unification/label_mappings.yaml`
Relation mappings: `src/unifiedsciere/unification/relation_mappings.yaml`

See [datasets.md](datasets.md) for the full mapping tables.

### 4. Dataset-Specific Corrections

**Module:** `src/unifiedsciere/unification/gsap_specific_corrections.py`

Currently only GSAP has corrections enabled. The GSAP model over-predicts
generic method references ("the model", "our approach", etc.). The correction:

1. An analysis step identifies GSAP predictions with no match in SciER/SciNLP
2. Texts appearing >= `min_count` times are collected into a filter list
3. Mentions matching the filter list are removed

The analysis JSON is generated by `src/unifiedsciere/unification/gsap_specific_analysis.py`
and referenced from the config.

### 5. Normalize Spans

Strips systematic prefixes/suffixes that differ between annotation schemes
(e.g. leading determiners like "the", "a", "our" on method mentions).

## Configuration

**File:** `configs/unification_config.yaml`

```yaml
merge_stacked:
    enabled: true
    prefer_larger: true

drop_unmapped:
    enabled: true

map_labels:
    enabled: true

dataset_corrections:
    gsap:
        enabled: true
        mlmodelgeneric_analysis_file: "reports/ere_confusion_analysis/unification/gsap_analysis/..."
        min_count: 2
    scier:
        enabled: false
    scinlp:
        enabled: false

pipeline:
    verbose: true
    generate_reports: true
    report_output_dir: "reports/ere_confusion_analysis/unification/pipeline"
```

## Pipeline Statistics

`apply_unification_pipeline` returns a `stats` dict with counts for each
step (mentions merged, dropped, mapped, filtered) for both gold and predicted
data. Use `generate_pipeline_report(stats, path)` to write a markdown summary.
